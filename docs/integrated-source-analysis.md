# 바리스 II 한글화 자료 통합 분석

이 문서는 Disk A–G와 KANJI1 ROM의 한글화 자료를 게임 영역과 저장 구조별로 분석한다. 일본어 원본 실행 흐름, 번역 문안, 패치 주소·바이트, 최종 빌드 결과를 서로 구분해 기술한다. 결과 대조의 기준은 원본 파일에 최종 패치를 새로 적용해 만든 산출물이다.

## 분석 기준과 주소 단위

RAM 주소는 게임 실행 중 메모리 위치이며 D88 raw 오프셋과 같은 주소가 아니다. 아래 raw 위치는 D88 파일의 섹터 헤더를 제외한 데이터 바이트를 가리킨다. 한 섹터의 데이터는 0x400바이트이고 섹터 헤더는 0x10바이트다. RAM에서 연속된 범위가 raw 파일에서는 헤더 간격을 두고 나뉠 수 있다.

표의 숫자는 집계 단위에 따라 달라진다. 실행 행에는 문자뿐 아니라 종료·분기·서브스트림 호출과 복귀가 포함된다. 번역 위치는 표시 문자 슬롯, payload 크기는 스트림의 제어 바이트를 포함한 영역, 매니페스트 행은 최종 빌드의 원시 패치 레코드다. 실제 변경 바이트는 같은 위치의 원본과 최종 값이 다른 바이트만 센다. 서로 다른 단위의 행 수를 빼서 누락된 게임 행을 추정하지 않는다.

작업표에 있는 슬롯 번호는 중복되거나 빠진 경우가 있다. 최종 반영 여부와 주소 대응은 순번만으로 정하지 않고 원본 바이트, RAM 주소, raw 오프셋, 종료·호출 흐름을 함께 확인한다. 각 디스크의 같은 일본어 안내 문구도 물리 사본과 포인터가 다르면 별도 영역으로 취급한다.

## 공통 실행·문자 표시 구조

부팅 및 오프닝 진입 경로는 F000 로더에서 3000 실행 영역으로 이동한 뒤 C000 초기화와 C01A 이벤트 처리로 이어진다. 메뉴 문자열은 화면의 그래픽 저장 주소와 별도다. Disk A 메뉴에서는 C227이 HL=C305를 준비하고 C588 문자열 출력 루틴으로 넘긴다. 1Axx/1Bxx 주소는 해당 메뉴 글자의 문자열 주소가 아니다. C305 문자 RAM과 대응 raw 0x16C6을 따로 바꿔 화면 반응을 확인한 기록이 이 구분을 뒷받침한다.

문자 토큰은 C671 계열 처리에서 제어 토큰과 표시 문자로 분기한다. 표시 문자는 0AEE 경로에서 JIS 바이트를 KANJI ROM 접근값으로 변환한 뒤 32바이트 글리프를 읽는다. 토큰 바이트를 d,e라 할 때 d<0x30이면 bank=((e>>1)&0x30), 아니면 bank=((e<<1)&0xC0)이며, hi=(((d<<1)|((e>>4)&1))&0x3F)|bank, lo=(e<<4)&0xF0로 접근값을 만든다. 예를 들어 6F 5E는 9F E0이고 실제 글리프 시작 위치는 접근값의 2배다.

16·17 계열 바이트는 일반 문자와 달리 서브스트림 호출과 복귀로 쓰인다. 호출 뒤에는 다른 주소의 문장을 읽고 복귀하며, 같은 HL에서 반복되는 C604는 대기일 수 있다. 따라서 토큰 소비는 행 번호가 아니라 입력 주소의 이동과 복귀 포인터로 확인한다. 예시 추적에서는 토큰 101의 DA25–DA26=82 AA가 C671→C692→B12C/B17D→0AEE/0A97→C0A2 경로를 지나 HL=DA27에 도달했다. 토큰 342는 예상표의 값 대신 DC04 원시 덤프와 DE=8D55에서 시작해 8D55→3936→7360을 지나 HL=DC06에 도달했다. 줄 경계 예시는 CA12+2=CA18, CA13+0C=CA19이며 출력 메모리 주소는 C000+CA12+CA13×50=EDB6으로 계산된다. 이는 해당 로그의 주소 산출을 검증하지만 CA14/CA15의 전체 의미나 화면 스크롤 전체 원리를 대신 설명하지 않는다.

효과음과 PCM 자막은 일부 공용 호출 경로를 공유한다. C692의 문자 처리 효과음 호출은 A420 공용 경로로 이어진다. A420 전체를 RET로 바꾸면 PCM 출력뿐 아니라 메뉴 효과음도 사라질 수 있다. 최종 설계는 원본 공용 코드를 보존하고 C692 호출점의 PCM 조건을 D960에서 처리한다. PCM ON은 원래 출력 경로, OFF는 원본 효과음 경로로 나뉜다. 상태값 0017H, A420=C3 EA B0, 호출점 분기 및 ON/OFF 메뉴 동작은 최종 동작 기록과 연결된다.

프롤로그에서는 공용 코드를 디스크에서 영구 변경하면 이후 Disk A 로더 블록 재적재 때 후크가 다시 나타날 수 있다. 최종 TEST9 패치는 D88 공용 코드의 0845=C3 F2 09, C692=CD 20 A4, C16E=C8을 원본으로 두고 D974=1E 6C DD에서 DD6C 일회 트리거를 건다. 래퍼는 RAM의 세 지점을 활성화하고 DD6C의 첫 세 바이트를 즉시 2A 4F A4로 복원하며, 세 처리가 끝나면 D930이 공용 RAM 지점을 원복한다. 프롤로그 진입과 엔딩 진행을 포함한 최종 게임 플레이 검증, 화면 표시 및 PCM 동작 확인이 이 구조의 실행 근거다. TEST9의 직접 raw 변경 구간은 0256E 1바이트, 02AA3–02AA4 2바이트, 06D66–06D67 2바이트, 08A83 1바이트, 08A9B–08AD1 55바이트, 08F0C–08F0E 3바이트로 총 64바이트다. 전체 프롤로그 매니페스트에는 텍스트·글리프 패치도 포함되므로 TEST9 코드 변경량과 전체 프롤로그 변경량은 다른 범위다.

저주소 디스크 오류 화면은 이벤트 스트림의 대사가 아니라 상주 RAM 출력기에서 생성된다. RAM 0600–06FF의 출력 루틴과 동적 문자·드라이브 번호 저장소를 사용하며, 같은 계열 문구가 Disk A, B, C, F, G에 각기 다른 슬롯 형식으로 복사돼 있다. 문장 길이가 변해 동적 번호 슬롯이 이동하면 문자열 바이트뿐 아니라 LD (nn),A 피연산자도 함께 확인해야 한다.

## Disk A: 프롤로그·메뉴·타이틀·엔딩·크레딧

### 프롤로그와 메뉴

메뉴 UI의 문자열 구간 C2F6–C40B는 D88 raw 16B6–17DB에 대응한다. 끝 항목 C3FE–C40B의 raw 데이터는 17BE–17BF와 17D0–17DB로 분리되고, 그 사이 17C0–17CF는 섹터 헤더다. RAM 문자가 연속돼도 raw 파일은 연속되지 않는 사례다. UI 작업표는 메뉴 17항목, 저주소 안내 3항목, 로딩 문구 3항목을 나눈다. 메뉴의 처음 6개는 번역·재인코딩 대상이고 나머지는 원문 유지다. 번역이 비어 있는 행을 패치 적용 행으로 세지 않는다.

로딩 표시는 숫자 C8B6–C8C9의 20바이트 영역과 문자열 C8CA–C8D3의 10바이트 영역을 분리한다. 후속 1CB4–1CB6의 00 세 바이트 및 C8D4/C8D5 경계에 관한 작업표 기록은 서로 한 바이트 차이가 난다. 이에 따라 C8D4를 확정 종료 주소로 단정하지 않는다. A/1처럼 고정된 문구와 G/2처럼 실행 중 들어가는 디스크 문자는 구분한다.

오프닝 일본어 스트림은 D974에서 시작하는 원본 자료로 분석됐으며, D974–DD69 1,014바이트 세트와 D974–DDF5 1,154바이트 확장 세트가 별도로 기록돼 있다. D974–DBFF는 652바이트, DC00–DD69는 362바이트이며 raw 데이터는 각각 08B04–08D8F 및 08DA0–08F09다. 그 사이 08D90–08D9F는 섹터 헤더다. DD68=26은 스트림 종료이고 뒤의 DD69=09는 후속 코드·데이터 흐름이다. 종료 바이트를 포함하는지 여부에 따라 D982–DD68은 999바이트, D982–DD69는 1,000바이트가 되므로 경계를 분명히 해야 한다.

오프닝 자료에는 원본 실행 552항목 분석과 한글 재인코딩·이전 일본어 런타임 로그를 한 행에서 비교한 545항목 검증표가 있다. 이 표들은 행의 기준이 다르므로 545와 552의 차이를 미검증 행 수로 보지 않는다. 이벤트 본류, 후크, 제어행, 화면 준비·스크롤, 서브스트림을 주소별로 확인한다. 원본 화면 추적에서는 #190–203이 화면 준비·스크롤, #204의 83 4F부터 표시 문자로 관측됐다. 오프닝의 16·17 호출·복귀와 음성 인덱스 27개, 얼굴 슬롯 41·42개는 이벤트 토큰·호출·음성·얼굴 처리의 별도 경로로 다뤄야 한다. 애니메이션과 호출이 인접해 있다는 사실만으로 둘의 인과를 정하지 않는다.

오프닝 검증 자료의 토큰 목록에는 544·545 표제와 본문 545행, 원본 실행표 552항목처럼 행수 차이가 있다. D974–D981의 후크 공간 주장도 재빌드에서 사용한 영역과 구분해야 한다. D974–D97F는 후크 코드 말미와 겹칠 수 있고 D980–D981은 00으로 기록된 바이트다. D974–D983을 여유 공간으로 간주하면 D982 본류 두 바이트를 덮는다. 삭제 후보 구간은 DD09–DD1C 20바이트, DD1E–DD1F 2바이트, DD21–DD28 8바이트, DD46–DD59 20바이트로 합계 50바이트다. 따라서 25개 2바이트 행의 삭제량 48바이트와 같다고 단정할 수 없다. 현재 빌드에서는 해당 옛 행 번호를 계산 기준으로 쓰지 않고 매니페스트의 명시 raw 주소와 원본·결과 바이트를 사용한다.

PCM ON 자막 경로, 효과음 호출점, 202·203행 출력 보정은 별도 수정 항목이다. 원본 실행 기록의 D900 진입 포인터는 DB0A/DB0C다. 현재 한글 빌드에서는 두 행이 DB06–DB07과 DB08–DB09에 놓여 소비 후 포인터가 DB08/DB0A가 되며, 패치 본문은 이 주소에 맞춰 16비트 차이 0/2와 카운터 02를 사용한다. 두 주소쌍은 원본 실행 배치와 현재 한글 배치의 값이다. 효과음 분기에서는 공용 A420 경로를 보존한다. 최종 프롤로그 빌드 변경에는 UI, 텍스트 스트림, PCM 분기, TEST9 래퍼와 ROM 글리프 데이터가 포함된다.

### 타이틀 CG와 스크롤

Disk A 타이틀은 네 개 자원으로 구성된다. ヴァリス 로고는 376×91 3-plane 압축(최대 0x1346바이트), II는 152×79 3-plane 비압축 interleave, 夢幻戰士는 RAM 1908–1EF7의 352×17 3-plane 압축(최대 0x05F0바이트), 스크롤 글씨는 RAM 1EF8–21B7의 352×16 1bpp다. 한 화면의 로고처럼 보여도 형식·크기·경계가 다르다.

자원은 Disk A의 12개 섹터에서 RAM 1900–48FF로 적재된다. D3FB–D404의 요청은 DE=2801, BC=0C00, HL=1900이며 RAM 포인터 [1900]=0008, [1902]=05F8, [1904]=08B8, [1906]=1A4F가 각각 1908, 1EF8, 21B8, 334F 경계를 만든다. raw 섹터 대응은 다음과 같다.

|---|---|---|
| T28/S01 | 1900–1CFF | 032BF0–032FEF |
| T28/S02 | 1D00–20FF | 033000–0333FF |
| T28/S03 | 2100–24FF | 033410–03380F |
| T28/S04 | 2500–28FF | 033820–033C1F |
| T28/S05 | 2900–2CFF | 033C30–03402F |
| T29/S01 | 2D00–30FF | 034040–03443F |
| T29/S02 | 3100–34FF | 034450–03484F |
| T29/S03 | 3500–38FF | 034860–034C5F |
| T29/S04 | 3900–3CFF | 034C70–03506F |
| T29/S05 | 3D00–40FF | 035080–03547F |
| T2A/S01 | 4100–44FF | 035490–03588F |
| T2A/S02 | 4500–48FF | 0358A0–035C9F |

각 raw 범위는 0x400 데이터만 포함하고 0x10 헤더를 건너뛴다. 12개 범위를 raw 파일에서 하나로 이어 덮으면 섹터 헤더와 후속 포인터를 손상시킨다.

변경된 ヴァリス 로고의 중앙행 순서를 유지하기 위해 Disk A D473–D475의 CALL 8719(바이트 CD 19 87)를 NOP 세 바이트로 바꾼다. raw 위치는 85F3–85F5다. 바깥쪽 행 이동과 Y99/Y100 중앙행 삽입 이후 호출이 45·46행을 서로 바꾸기 때문에 한글 그림의 순서와 맞지 않는다. 뒤의 D47A–D48C 스크롤 이동은 유지한다. 타이틀 보정의 QUASI88 실행 확인과 네 타이틀 자원의 인코딩·전투 CG 적용은 빌드 구성에서 각각 별도 자원으로 관리한다.

### 엔딩과 크레딧

엔딩 본류 D149–D891은 1,865바이트이며 D891=26에서 끝난다. 실행 순서 1,132항목은 본류 934행과 서브스트림 198행으로 구성된다. 세 D88 조각은 D149–D3FF 695바이트/raw AF69–B21F, D400–D7FF 1,024바이트/raw B230–B62F, D800–D891 146바이트/raw B640–B6D1이다. B220–B22F와 B630–B63F는 섹터 헤더다. 2D FF 명령에서 CA23에 FF를 쓰는 것은 확인됐지만 FF의 상위 의미는 원본 분석 기록에서 정하지 않았다. 신규 글리프 접근을 기록한 행은 ROM 접근 근거이며 별도의 화면 확인 사실과 혼동하지 않는다.

번역 워크북은 본류의 15개 call 그룹, 840개 문자 위치를 번역 단위로 배열하고 전각 공백 81 40을 별도 표시한다. 화자 ID는 토큰 자료만으로 지정하지 않는다. 한글 패치표는 840 위치를 한글 547, 전각 공백 155, 문장부호 132, 특수 6으로 분류한다. 제어행과 서브스트림은 문자 위치와 별도다. 슬롯 번호는 단독 키가 아니다. 예를 들어 0070이 서로 다른 행에 반복되고 0072가 빠지며, 0105와 0836도 중복 표기된다. raw 주소와 원본·결과 바이트로 대조해야 한다.

엔딩 호출 예에서는 런타임표의 D983=17 복귀가 패치표의 같은 주소·바이트와 대응한다. 뒤 본류 D606=41은 재배치 후 D620=41로 이동했고 행 순번도 달라졌다. 앞의 D603–D605 호출 및 D965 호출도 패치 스트림에서는 각각 옮겨져 같은 처리 흐름을 유지한다. 다만 일부 작업표에는 시작부 D601–D61A의 13개 문자행이 있고, 원본 D601–D602는 61 62 제어행으로 기록돼 있다. 이 행 라벨끼리의 대응은 성립하지 않는다. 최종 빌드 적용은 활성 패치 정의의 raw 주소 및 원본 바이트를 기준으로 확인한다.

### 음악 모드

곡 정보는 33개×12바이트 record C64C–C7D7, 종료·포인터 36바이트 C7D8–C7FB, 제목 C7FC–CB2F, 작곡자 CB30–CB50로 나뉜다. 제목 항목은 작곡자 인덱스 1바이트, Shift-JIS 제목, 00 종료로 구성되고 포인터는 record 시작 다음 바이트를 가리킨다. 뒤의 원본 作曲 데이터 CB51–CB55와 Ｄｉｓｋ CB56–CB5E는 유지한다.

한글 패치에 따른 내부 배치는 제목 804바이트 C7FC–CB1F, 작곡자 47바이트 CB20–CB4E, 남는 00 두 바이트 CB4F–CB50다. 33개 제목 포인터와 작곡자 CB20/CB2F/CB3C 포인터를 새 위치로 계산한다. 作曲 출력은 C118의 CALL 세 바이트를 00으로 막고, C12F의 DE 참조는 D41A에서 D414로 이동한다. 作曲 원문 데이터 자체는 보존한다. D88 raw는 C7FC–C7FF가 301C–301F, C800–CB50이 3030–3380이며 raw 3020–302F 섹터 헤더를 건넌다. 제목·작곡자 표시와 음악 메뉴 실행이 사용자 확인 대상이다. E000 적재 관찰은 음악 텍스트 패치와 분리한다. 8-sector 적재 중 00 FF… 메모리 값은 관측됐지만 write PC와 명령은 추적하지 않았다. 별도의 39/1/5 단일 섹터 시험은 4001 스텁과 C01E 호출을 통해 4F05→E000을 확인했다. 01ED 경로는 실행 대상이 아니었고 0167 경로는 기존 검사와 충돌해 채택하지 않았다. 12바이트 곡 record 내부 필드의 전 의미를 제목 번역 결과에서 추정하지 않는다.

### DISK 경고

0/0/8 경고문은 RAM 065F–06E3/raw 0A8F–0B13의 133바이트 슬롯이고, 39/0/5는 RAM 0613–06B8/raw 64026–640CB의 166바이트 슬롯이다. 번역은 각각 129바이트와 164바이트를 사용하고 나머지를 00으로 채운다. 첫 블록에서는 동적 문자·드라이브 번호가 이동하여 0630·0649의 주소 피연산자도 함께 바뀐다. 두 번째 블록의 동적 A 값은 RAM 0673/raw 64086이며, 진입점 RAM 0668/raw 64016 및 LD (0673),A 명령 raw 64010과 연결된다. 문자열 A 영역은 이동하지 않으므로 이 주소 확인만으로 코드 피연산자를 임의 수정하지 않는다. 두 문구의 표시 성공은 사용자 실행 기록에 있다.

### Prize 알림

Prize 안내는 C28/H0/R1–4의 4,096바이트 payload 안에 있으며 본문은 C6E5–CB3E, 1,114바이트다. C6E5–CA9C에는 2바이트 문자 476개, CA9D=01에는 긴 간격 제어, CA9E–CB3D에는 2바이트 문자 80개, CB3E=00에는 루프백 제어가 있다. D88 raw 본문은 477E5–478FF와 47910–47C4E로 갈리고 47900–4790F는 섹터 헤더다. 알림은 오른쪽에서 왼쪽으로 반복 스크롤한다. 한국어 문안은 21개 구획으로 나뉜다. 제어 바이트 01과 00은 고정 위치이므로 번역 길이는 일반 문자 위치 안에서 맞춘다. 현재 빌드 패치표는 48개 연속 raw 변경 레코드이며 실제 변경량은 1,022바이트다.

## KANJI1 ROM과 게임 설명서

KANJI1 글리프표는 최종 558개 배정 행을 사용한다. 이전 분석 자료의 123·361·558개 배정판은 글리프 주소 배치가 서로 다르며 조합할 수 없다. 입력 원본 ROM은 131,072바이트, SHA-256 `7608040cffb1951e5cc567abb63f75b5746777a1ba96196c1b75606b793bb4bb`다. 최종 한글 ROM은 이 원본에 558개 글리프표만 적용하며 SHA-256은 `e5646601d83fc2685340a183fa50d3c4fca8daf449acefc35544ef790e775aab`다. 원본에서 달라지는 16,820바이트는 558개 지정 글리프 슬롯 안에 있고 나머지 주소는 원본값을 유지한다. 글리프 토큰 주소는 0AEE 변환과 연결하되, 표의 배정 행수 자체를 화면 확인 문자 수로 보지 않는다.

게임 설명서는 28쪽이고 번역본은 4–9쪽에 부팅·조작·시스템·스테이지·HUD·장비·아이템 안내가 있다. 4쪽은 PC-88/98에서 Disk A를 drive 1, Disk B를 drive 2로 넣는 방법과 Sound Board II 사용 시 Disk G 안내를 다룬다. 5쪽은 F5 음악 모드, 6쪽은 여섯 스테이지와 HUD, 7쪽은 장비·HP·주얼, 8–9쪽은 아이템 유형이다. 이 내용은 플레이 절차의 문맥이며 D88의 코드 경로 및 raw 패치 주소를 대신하는 증거는 아니다.

## 분석 종합

바리스 II 한글화는 이벤트 문장만 바꾸는 작업이 아니다. 메뉴·저주소 화면·이벤트 스트림·호출형 서브스트림·동적 디스크 번호·음악 목록·경고·Prize·KANJI1 글리프·타이틀 및 전투 CG가 각각 다른 주소와 출력 경로를 쓴다. 고정 길이 슬롯, 제어 바이트, 동적 store, 섹터 헤더, 포인터 이동을 각 영역에 맞춰 처리해야 한다.

최종 패치 정의는 영역별 raw 주소와 원본 바이트를 기준으로 일본 원본에 적용되며, D88 A–G와 KANJI1 ROM의 파일 크기·변경 위치·SHA-256은 위 표에 정리한 최종 출력과 일치한다. 사용자 게임 진행 확인은 해당 기능과 빌드 범위에 연결하고, 작업표의 행 라벨이나 과거 번역표의 집계만으로 최종 적용 여부를 대신 판단하지 않는다.
